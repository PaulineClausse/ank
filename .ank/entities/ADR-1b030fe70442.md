## Context

`git clone` does not carry `remote.origin.fetch`: a refspec is local git
configuration, and no file in the repository can ship it. Every fresh clone of
an ank repository therefore starts without `+refs/ank/*:refs/ank/*`, and stays
without it until somebody reads the warning `status` prints and runs `ank init`
again. Detection is complete (TASK-623d, TASK-f067, TASK-eff5); the repair is
manual.

Measured on 2026-10-11, on this repository at fb17a26a:

- a fresh `git clone` of origin holds 0 refs under `refs/ank/`, against 218 on
  origin (214 under `refs/ank/proof/`);
- `ank check` in that clone exits 0 with 744 signals, 214 of them `done with no
  test proof: nothing external anchors it`;
- the same corpus with the refspec added and fetched gives 531 signals and 0 of
  that kind.

So the default state of every clone is a `check` that asserts, 214 times, an
absence it cannot observe: the attestations exist on origin, written by the
`attest` job. Arbitration is not affected (`claim` reads origin first, and the
push settles races), but the record is.

## Decision

A verb that already runs git (ADR-9307e5d214a7) and finds a remote named
`origin` whose fetch configuration lacks `+refs/ank/*:refs/ank/*` adds it, then
runs one `git fetch --quiet origin '+refs/ank/*:refs/ank/*'`, and says both on
stderr in one line. It happens once per clone, at the transition: a clone that
has the refspec pays nothing. A fetch that fails (offline, unreachable origin)
is not an error; the refspec stays written and the next `git fetch` brings the
refs.

A verb that does not run git starts no git process for this.

This amends ADR-47e2ac102f58 in part: that ADR keeps every verb from fetching
to close the gap between the checkout and the default branch, and it still
does. The fetch here touches `refs/ank/*` only, never a branch nor an entity
file, and only on the transition that writes the refspec.

## Consequences

- `status` stops warning and `check` stops signalling the missing refspec in
  practice, since the first git-running verb repairs it; both keep the
  detection for a clone where the write itself failed.
- With no `origin`, nothing is written: the refusal TASK-f067 fixed
  (`git remote add origin` refused by a pre-written `remote.origin.fetch`) stays
  fixed.
- A verb that only reads now writes git configuration once. That is the trade
  taken, by the human, on 2026-10-11: a self-repairing default over a reader
  that never writes.
