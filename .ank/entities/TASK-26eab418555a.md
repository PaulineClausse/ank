## Goal

`done` runs the verifiers of a task concurrently, bounded by a configurable
limit, so that several agents on one machine do not saturate it.

Today `run_verifiers` in `crates/ank-cli/src/done.rs` walks the declared list
in a `for` loop, one `verify::run` after another, and stops at the first
failure, discarding every proof already gathered. `done` therefore costs the
sum of its verifiers.

## Shape

- A new top-level key `verifier_jobs` (a positive integer) bounds how many
  verifiers of one `done` run at once. Absent, it defaults to the machine's
  available parallelism. It is written through `ank config verifier_jobs <n>`
  like every other key (ADR-e64dfaafd578) and listed in the key table.
- Proof entries are gathered in the declared order of `verify:`, whatever the
  order of completion, and are byte-identical to what a sequential run writes.
- On the first failure in declared order, the verifiers still running are
  killed, nothing is recorded, and `done` exits with the code and message that
  verifier would have produced sequentially (5 for a refusal or a timeout, 9
  for an environment that would not run it).
- The `running: <name> ... ok` lines on stderr stay one per verifier.

Independent of ADR-d8a328e311b9 and ADR-a2faf59f6ce0.

## How to prove it without a stopwatch

CLAUDE.md asks for concurrency to be shown by what happens, not by a wall
clock. Two verifiers that each create a marker file and then wait for the
other's marker, under a short timeout, can only both pass if they run at the
same time: under `verifier_jobs: 2` the `done` succeeds, under
`verifier_jobs: 1` the first one times out and `done` exits 5.
