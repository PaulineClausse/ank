## Context

`done` is the slowest step of the loop, and most of an agent's runs of the
test suite happen before it, while the work is in progress, through raw
commands ank never sees. ADR-a2faf59f6ce0 makes `done` reuse a passing result
whose content key has not changed, and rejects verifiers made incremental from
changed files for the proof: such a proof would depend on a base commit and
stop proving what it states. The same ADR names a verb like this one as
useful later, so agents get feedback through ank rather than raw commands.

The need is not specific to this repository. A user with `packages/api` and
`packages/web` wants the test of the package they did not touch to stay out of
the way while they work, in any language.

## Decision

1. **Selection by change, for feedback only.** `ank verify` runs the declared
   verifiers whose `inputs` (ADR-d8a328e311b9) match a changed file: changed
   since the merge-base with the default branch, modified in the working tree,
   or untracked and not ignored. A verifier without `inputs` reads the whole
   tree, so it is always selected.
2. **Never a proof.** It writes no proof entry, no ref and no entity, and needs
   no claim. A selection made from a diff depends on its base, which is exactly
   why ADR-a2faf59f6ce0 keeps it out of a proof, and it stays out here.
3. **Its runs feed the registry.** This is the part of ADR-a2faf59f6ce0 it
   amends: that ADR records runs made by `done`; runs made by `verify` are
   recorded too, keyed by the same content digest. Reuse stays content-keyed,
   so a `done` that reuses one proves exactly what an execution would have:
   this definition passed on these bytes, on this machine, within the age
   bound. Whether a run was selected by a diff never enters the key.

## Consequences

- The working loop costs the verifiers a change touches, and the `done` that
  follows costs only what changed since the last `verify`.
- A verifier with wrong `inputs` can be skipped by `verify` where it should
  have run. `done` still keys on content, and a verifier without `inputs` is
  never skipped, so the proof is not weakened by it.

## Rejected alternatives

- `done` selecting by diff: rejected by ADR-a2faf59f6ce0 for the proof, and not
  reopened.
- A selection that records itself: a list of skipped verifiers on a proof would
  read as a claim about them.
